# Connector 3000 V3 Implementation Plan

> **Implementation record:** Completed local work and verification gaps are marked below.

**Goal:** Build a secure public MCP gateway and local Windows worker that let ChatGPT invoke the local Codex CLI without the failing managed SSE tunnel.

**Architecture:** A stateless Streamable HTTP MCP gateway authenticates ChatGPT requests and persists jobs in PostgreSQL. A single local worker maintains an outbound authenticated WebSocket, claims jobs with database fencing, and runs Codex in the fixed project root; results and Codex session IDs return through durable job state.

**Tech Stack:** Node.js 22+, JavaScript ES modules, `@modelcontextprotocol/server` 2.3.1, `@modelcontextprotocol/node` 2.1.1, Zod 4.2.0, `ws` 8.22.0, `pg` 8.23.1, PostgreSQL, Node built-in test runner, Railway.

**Spec:** `docs/superpowers/specs/2026-10-07-connector-3000-v3-design.md`

**Implementation record:** Completed local work and verification gaps are marked below.

## Global Constraints

- Node.js runtime is 22 or later; worker runs on the user's Windows machine.
- Public MCP transport is Streamable HTTP at `/mcp`; do not use legacy two-endpoint SSE.
- MCP uses the 2026-07-28 stateless protocol with the SDK's stateless legacy fallback; application job IDs and Codex `session_id` values carry durable state.
- Keep tool names `codex_project_status`, `codex_ask`, and `codex_implement`.
- `codex_project_status` and `codex_ask` are read-only; `codex_implement` uses `workspace-write`; never request `danger-full-access`.
- Worker has one configured `NOVA_PROJECT_ROOT`; reject canonical paths outside it, including symlink escapes.
- Gateway and worker use distinct revocable credentials; never log tokens or environment values.
- Retry policies are bounded, honor `Retry-After`, and add jitter; uncertain implementation jobs are never automatically replayed.
- Same Codex session jobs execute serially; independent sessions have a bounded concurrency cap of 2.
- Accept at most 10 queued/running jobs for the one configured worker; reject additional work with a typed busy response.
- Prompt/result bodies are deleted after retrieval or 24 hours; sanitized job metadata is retained for 30 days.
- Do not change Nova application files or create a second Canonical MCP source of truth.
- This Nova V2 workspace is not a Git checkout; do not claim commits. Develop V3 in `Nova V2/connector-v3/`; publishing to GitHub and provisioning Railway are separate deployment actions.

## Review Focus

- Worker disconnect after implementation side effects: leave job `indeterminate`; assert a reconnect never dispatches the implementation again (Tasks 2 and 5).
- A stale worker reconnects while a previous socket is open: fence its generation and allow only one worker to claim jobs (Task 4).
- Two requests use the same Codex session: serialize execution and preserve the returned session ID (Task 5).
- Gateway returns 429 with or without `Retry-After`: honor the header or use capped exponential backoff with jitter; 404 must not retry (Task 4).
- Windows paths, missing `codex.exe`, and spawn denial: reject root escape and return typed sanitized execution errors (Tasks 1 and 5).
